## 4. 上传、媒体与存储

| 需求 | 状态 | 当前情况 |
| --- | --- | --- |
| JPG/PNG/MP4 与大小限制 | 已实现 | 图片 100MB、视频 500MB。 |
| 批量上传、8MB 分片、3 次重试、断点续传 | 已实现 | 上传 ID、ETag 和已完成媒体 ID 保存在本机；重新选择同一文件可继续。 |
| 解析 → 批量确认城市 → 正式上传 | 已实现 | 上传前读取类型、大小、SHA-256、JPEG 拍摄时间和可用 GPS。 |
| 原图、网页图、缩略图和隐私安全原尺寸副本 | 已实现（图片） | 浏览器 Canvas 生成的派生 JPEG 不含 EXIF；R2 保留私有原图。 |
| 视频海报与转码 | 部分实现 | 字段、R2 路径和上传接口已预留；MP4 原文件可由上传者/管理员播放，自动海报和隐私安全转码仍未实现。 |
| 城市全站最多 500 张 | 已实现 | D1 触发器处理并发竞争，不能通过同时上传绕过。 |
| 精确重复检测 | 已实现（常规文件） | 120MB 以内文件在浏览器计算 SHA-256；更大视频不做浏览器整文件哈希。 |
| PNG 无时间进入待完善 | 已实现 | 不参与自动旅行日期；媒体库可批量前逐项补充。 |
| 说明、标签、移动城市、手动排序 | 已实现 | 移动目标仅限旅行已包含城市；拖放顺序一次性保存。 |
| 智能相似排序 | 已实现（轻量算法） | 结构 dHash 权重 82%，主色相 18%；明确不做人脸身份识别。它是可迁移的视觉相似算法，不是云厂商专属 AI。 |
| 30 天回收站与恢复 | 已实现 | 旅行和媒体保留删除前状态；Cron 到期删除 R2 原图/派生图和 D1 记录。 |
| 8GB 预警、9GB 停止上传 | 已实现 | 原图与派生图都做并发预占；达到预警线向管理员发邮件，达到硬上限拒绝上传。 |
| 动态照片配对 | 部分实现 | MP4 可作为独立媒体保存；DJI/荣耀照片与 MP4 的自动配对尚未实现。 |

## 7. 仍需真实素材/生产环境验收

以下不再是代码骨架缺失，但上线后仍需人工验收：

1. 使用一组 DJI Pocket 与荣耀真实 JPG/MP4 检查 EXIF 时间、GPS 区县识别和动态视频兼容性。
2. 使用约 700MB—1GB 批次验证浏览器长时间上传、断网后重选同一文件续传，以及派生图额外存储量。
3. 用多名受邀账号验证邀请邮件、冻结后会话失效、点赞名单与私人收藏隔离。
4. 视频自动海报、元数据安全转码与 DJI/荣耀动态照片自动配对仍是明确的后续增强项；在实现前不会向非上传者提供视频原文件下载。
